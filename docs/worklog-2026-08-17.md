## Activity (สิ่งที่ทำ)
- ตรวจสอบ audit เดิมใน `docs/pii-masking-claude-code-prompt.md` กับโค้ดจริงก่อนลงมือ พบ 3 ข้อไม่ตรงกับของจริง (มีจุด dispatch เพิ่มอีก 3, listener อ่าน `newValue` จริงไม่ได้อ่านจาก IndexedDB, มีสำเนา case list ใน `localStorage` ที่ไม่มีใครล้าง) จึงปรับแผนก่อนแก้
- **แก้ข้อมูลรั่ว 3 จุด:** รวมการล้าง IndexedDB + `localStorage` เป็นฟังก์ชันเดียวเรียกตอน logout, แทนที่การส่ง case list เต็มก้อนผ่าน `StorageEvent` ทั้ง 6 จุดด้วยสัญญาณเปล่า (พบและแก้ race condition ที่ `idbStorage.setItem` ไม่ได้ `await` ไปด้วย), ตัดข้อมูลระบุตัวตนออกจาก log ใน `hybridBaseQuery.ts`
- **สร้างระบบปิดบังข้อมูล:** โมดูล `piiFields.ts` แบบ zero-import กำหนด 22 field พร้อม 5 กลยุทธ์ fail-closed, hook `usePiiMasker()` ที่คืนฟังก์ชัน mask (ไม่ใช่ค่าที่ mask แล้ว เพราะบางจุดต้อง mask ภายใน `.map()`), และ `lockPiiInput()` สำหรับฟอร์มแก้ไข — ล็อกฟิลด์แทนการ mask เพราะถ้า render ค่า mask ลงใน input ค่านั้นจะถูกบันทึกทับข้อมูลจริงตอนกด save
- **นำไปใช้:** ปิดบัง 6 จุดแสดงผล + ล็อก 2 จุดฟอร์ม โดยล็อกเฉพาะตอนแก้ไข ไม่ใช่ตอนสร้างใหม่ (อนุมัติแล้ว เพราะตอนสร้างยังไม่มีข้อมูลให้ปกปิด)
- **แก้ไขจุดที่ mask ผิด:** เบอร์ติดต่อของเคสเอง (`caseData.customerData`) ถูก mask ไปด้วยในรอบแรก ทั้งที่เป็นคนละข้อมูลกับเบอร์ที่ลงทะเบียนไว้ในโปรไฟล์ลูกค้า (ผู้แจ้งอาจโทรมาจากเบอร์คนอื่น) แก้ให้แสดงปกติตามหลักที่ผู้ว่าจ้างยืนยัน
- **ขยายไปยังฟอร์มไดนามิก:** เพิ่มช่อง `pii` บน field ของฟอร์มลูกค้า, เพิ่มตัวเลือก "มีข้อมูลส่วนบุคคล" พร้อม preset การปิดบัง 4 แบบในหน้าออกแบบฟอร์ม (จำกัดเฉพาะ field ประเภทข้อความ/ตัวเลข/วันที่ที่ปิดบังได้อย่างปลอดเจน), เปิดใช้เฉพาะฟอร์มของลูกค้าเท่านั้น (ฟอร์มเคส/SOP ยังคงแสดงปกติผ่าน prop opt-in) ระหว่างทางพบและแก้บั๊ก stale closure ที่จะทำให้ SuperAdmin เห็นข้อมูลถูกปิดบังค้างแม้สิทธิ์โหลดเสร็จแล้ว
- ตรวจสอบด้วย `tsc -b`, `eslint`, `pnpm build` ทุกครั้ง, ทดสอบพฤติกรรมการ mask ด้วย script ชั่วคราวรวม 112 เคส (ลบทิ้งหลังรัน ไม่เพิ่ม test framework)
