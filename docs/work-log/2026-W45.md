## Monday — 2026-11-02

### Boundary Geometry from Object Storage

**Spending Hour:** 5.5 hr.

**Activity**

- เปลี่ยนแหล่งข้อมูลรูปแปลงเขตการปกครองของแผนที่เคส จากเดิมที่อ่านไฟล์ static ครั้งละหนึ่ง level เป็นอ่าน geometry แยกรายพื้นที่จาก object storage โดยชื่อและลำดับชั้นของพื้นที่ยังมาจาก area API เดิม
- เพิ่ม module สำหรับสร้าง path ของ object แต่ละพื้นที่ พร้อมอ่านข้อมูลเป็น bytes ก่อน แล้วค่อย decompress เฉพาะเมื่อข้อมูลเป็น gzip จริง
- จำกัดจำนวน request ที่วิ่งพร้อมกัน และ cache geometry ต่อ URL ไว้ตลอด session รวมถึง cache ผลว่า "พื้นที่นี้ยังไม่มีรูปแปลง" เพื่อไม่ให้ยิง 404 ซ้ำทุกครั้งที่เปลี่ยน selection
- คำนวณสีของพื้นที่จาก adjacency ของ geometry ที่โหลดมา แทน color index ที่ฝังมากับไฟล์ static เดิม เพื่อให้พื้นที่ติดกันยังไม่ใช้สีซ้ำ
- เพิ่ม config สำหรับเลือกแหล่งข้อมูลและกำหนด base URL ของ bucket โดยตั้งใจไม่ใส่ค่า default ของ environment ใดเลย ถ้ายังไม่ตั้งค่าจะ fallback ไปใช้รูปแปลง static พร้อม log บอกสาเหตุ
- เขียน unit test ของการสร้าง path และการอ่าน geometry และตรวจ type/lint ของไฟล์ที่แก้

**Scope / Context**

- อยู่ในงานแผนที่เคส (boundary polygons) ซึ่งเดิมต้อง rebuild ทุกครั้งที่มีการแก้ไขรูปแปลง และอ่านค่า orgId จาก store ที่ไม่มีใครเขียนค่า จึงต้องเปลี่ยนไปอ่านโปรไฟล์ที่ persist ไว้ตอน login
- เลือก cache ผลลบไว้เพราะพื้นที่ส่วนใหญ่ยังไม่มีรูปแปลง ถือเป็นสถานะข้อมูลปกติ ไม่ใช่ error
- รูปแบบ object และ path เป็นข้อตกลงกับฝั่งที่เขียนข้อมูลขึ้น bucket จึงระบุไว้ในคอมเมนต์ของ module แทนการเดาจากนามสกุลไฟล์

**Outcome**

- รูปแปลงพื้นที่โหลดจาก storage ของแต่ละ environment ได้ และพื้นที่ที่ยังไม่วาดจะไม่ทำให้ทั้ง level หายไป
- ไม่มี default ที่ชี้ไป bucket ของ environment อื่น ถ้าลืมตั้งค่า ระบบยังแสดงรูปแปลงเดิมและบอกสาเหตุใน console
- พื้นที่ติดกันยังไม่ใช้สีซ้ำกันเหมือนเดิม แม้จะไม่มี color index จากไฟล์แล้ว

- สร้างชุด JSON payload ที่เทียบเท่ากันสำหรับสร้างข้อมูลผ่าน API ของผลิตภัณฑ์ พร้อม README อธิบายลำดับการเรียกและค่าที่ต้องแทนที่
