### Editable Area Boundaries on Organization Areas

**Spending Hour:** 5 hr.

**Activity**
- เพิ่มความสามารถให้กรอกและแก้ไขขอบเขต (map boundary) ของประเทศ จังหวัด และอำเภอ ได้โดยตรงบนฟอร์มในหน้า Area Management เดิมที่ขอบเขตมาได้ทางเดียวคือผ่านแม่แบบพื้นที่ (area template) เท่านั้น
- เพิ่มฟิลด์ shape area, shape length และ year of data สำหรับระดับประเทศ พร้อมขยายชนิดฟิลด์ของฟอร์ม (AreaFormModal) ให้รองรับ number/textarea และข้อความ hint ใต้ช่อง
- เพิ่ม validation ของค่าขอบเขตก่อนบันทึก เพื่อให้ค่าที่รูปแบบไม่ถูกต้องแจ้งเตือนที่ฟอร์มแทนที่จะไปพลาดตอนบันทึก
- เพิ่มยูทิลิตี `toCoordinatesPayload` ที่ใช้ร่วมกันทั้งฝั่ง org area และ area template เพื่อจัดการความต่างระหว่าง "ไม่ได้แก้" (ส่งค่าขอบเขตเดิมกลับไป ไม่ให้ถูกล้าง) กับ "ล้างค่า" (ส่ง array ว่าง)
- เพิ่ม endpoint สำหรับอ่านข้อมูลรายตัว (country/province/district by id) ทั้งฝั่ง REST และ mapping GraphQL
- แสดงป้ายที่มา (provenance) บนรายการพื้นที่ ระบุว่าประเทศใดถูกสร้างหรือซิงก์มาจากแม่แบบใด เพื่อแยกพื้นที่ที่สร้างเองกับพื้นที่ที่มาจากแม่แบบ
- อัปเดตคำแปลไทย/อังกฤษ/จีน และปรับไฟล์ตัวอย่าง (areaCURL.sh) ให้ตรงกับ payload ใหม่

**Scope / Context**
- อยู่ในโมดูล System Configuration ส่วน Area Management (CMS) ต่อยอดจากงานแม่แบบพื้นที่ก่อนหน้า โดยเปิดให้พื้นที่ขององค์กรมี geometry ของตัวเองได้โดยไม่ต้องผูกกับแม่แบบ
- หมายเหตุการออกแบบ: การส่ง coordinates เป็น array ว่างเพื่อ "ล้าง" ยังเป็นสมมติฐานที่ยังไม่ยืนยันกับ backend จึงจำกัดไว้ในจุดเดียว (`toCoordinatesPayload`) และฟิลด์ postcode ของอำเภอฝั่ง org ยังเป็น read-only ตาม input ของ backend

**Outcome**
- ผู้ดูแลสามารถกำหนด/แก้ไขขอบเขตและข้อมูลรูปทรงของพื้นที่ระดับองค์กรได้เองบนฟอร์ม การแก้ไขที่ไม่แตะขอบเขตจะไม่ทำให้ขอบเขตเดิมหาย และการเว้นว่างถือว่าไม่มีขอบเขต
- รายการพื้นที่แสดงชัดเจนขึ้นว่าประเทศใดมาจากแม่แบบ ช่วยแยกแยะข้อมูลที่สร้างเองกับที่รับมา ตรวจสอบแล้วว่าโปรเจกต์ผ่าน type check (`tsc -b`) สำเร็จ พร้อมอัปเดตบันทึกการเปลี่ยนแปลงเป็นเวอร์ชัน 0.56.0
