**Scope / Context**
- ครอบคลุมงานในโมดูลการตั้งค่าระบบและการจัดการพื้นที่ ได้แก่ หน้ารายการและรายละเอียดแม่แบบพื้นที่ หน้าจัดการจังหวัดและอำเภอ การแสดงขอบเขตบนแผนที่ การเชื่อมต่อ API และ GraphQL ชนิดข้อมูลและการจัดการผลลัพธ์ API การปรับปรุงหน้าจอจัดการพื้นที่เดิม เมนู เส้นทาง และคำแปล

**Outcome**
- เพิ่มความสามารถให้ผู้ดูแลสร้าง แก้ไข ดูประวัติ และเผยแพร่แม่แบบพื้นที่ได้ โดยแม่แบบที่เผยแพร่แล้วจะไม่ถูกแก้ไขโดยไม่ตั้งใจ สามารถนำแม่แบบที่เผยแพร่ไปสร้างหรือปรับปรุงพื้นที่ขององค์กรได้ ระบบจัดการพื้นที่มีโครงสร้างและการโต้ตอบที่ชัดเจนขึ้น รองรับข้อมูลหลายภาษาและการทำงานผ่าน REST/GraphQL พร้อมอัปเดตบันทึกการเปลี่ยนแปลงเป็นเวอร์ชัน 0.53.0 และตรวจสอบแล้วว่าโปรเจกต์ build สำเร็จ

### KMS Article Category Browser

**Spending Hour:** 3.5 hr.

**Activity**
- เพิ่มหน้าจอใหม่สำหรับเรียกดูบทความในคลังความรู้ (Knowledge Base) โดยแบ่งตามหมวดหมู่ พร้อมแผงต้นไม้หมวดหมู่ด้านข้างและช่องค้นหา
- เชื่อมต่อข้อมูลหมวดหมู่และรายการบทความผ่าน GraphQL พร้อมรองรับการโหลดบทความเพิ่มแบบ infinite scroll (Load more)
- ปรับโครงสร้างเมนู Knowledge ในแถบด้านข้างและเมนู More บนแถบด้านบน แยกหน้าจอ "จัดการบทความ" (สำหรับผู้ดูแล) ออกจากหน้าจอ "บทความ" ใหม่ (สำหรับเรียกดู) อย่างชัดเจน
- ปรับปรุงคำแปลภาษาไทยและอังกฤษของเมนูที่เกี่ยวข้อง

**Scope / Context**
- อยู่ในโมดูล Knowledge Management (KMS) ส่วนของบทความ (Articles) เพื่อให้ผู้ใช้งานทั่วไปเข้าถึงและค้นหาบทความในคลังความรู้ได้สะดวกขึ้นโดยไม่ต้องผ่านหน้าจัดการที่ออกแบบไว้สำหรับผู้ดูแลเนื้อหา
- คำแปลภาษาจีนของป้ายเมนูใหม่ยังไม่ได้อัปเดตในรอบนี้

**Outcome**
- ผู้ใช้งานที่มีสิทธิ์ดูบทความสามารถเข้าหน้าจอใหม่ "บทความ" จากเมนูด้านข้าง เพื่อไล่ดูตามหมวดหมู่และค้นหาบทความได้โดยตรง
- เมนูจัดการบทความ (สำหรับผู้ที่มีสิทธิ์จัดการ) ย้ายไปอยู่ในเมนู More บนแถบด้านบน แยกจากหน้าจอเรียกดูทั่วไป ลดความสับสนระหว่างสิทธิ์ผู้ใช้งานสองกลุ่ม
- ตรวจสอบแล้วว่าโปรเจกต์ผ่าน type check (`tsc -b`) สำเร็จ พร้อมอัปเดตบันทึกการเปลี่ยนแปลงเป็นเวอร์ชัน 0.54.0

- เพิ่มการรองรับลากไฟล์รูปภาพหรือเนื้อหาจากภายนอกเบราว์เซอร์มาวางลงในตัวแก้ไขได้โดยตรง
- ปรับการแทรกรูปภาพด้วยลิงก์ URL ให้ได้ผลลัพธ์เหมือนกับรูปที่อัปโหลด (จำกัดความกว้างและปิดการลากแบบ native)

**Scope / Context**
- อยู่ในโมดูล Knowledge Management ส่วนตัวแก้ไขเนื้อหาบทความ (ArticleCreateForm) และส่วนแสดงการ์ดบทความที่ใช้ร่วมกันหลายหน้าจอ (Case Panel, Knowledge Dashboard)

**Outcome**
- ผู้เขียนบทความสามารถจัดวางตำแหน่งรูปภาพในเนื้อหาได้สะดวกขึ้นโดยไม่ต้องลบแล้วแทรกใหม่ และสามารถลากไฟล์รูปจากเครื่องมาแทรกได้ทันที
- การ์ดบทความในคลังความรู้แสดงรายการได้มากขึ้นต่อการโหลดหนึ่งครั้ง ลดการต้องกดโหลดเพิ่มบ่อยๆ
- ตรวจสอบแล้วว่าโปรเจกต์ผ่าน type check (`tsc -b`) สำเร็จ พร้อมอัปเดตบันทึกการเปลี่ยนแปลงเป็นเวอร์ชัน 0.55.0

### Editable Area Boundaries on Organization Areas

**Spending Hour:** 5 hr.

**Activity**
- เพิ่มความสามารถให้กรอกและแก้ไขขอบเขต (map boundary) ของประเทศ จังหวัด และอำเภอ ได้โดยตรงบนฟอร์มในหน้า Area Management เดิมที่ขอบเขตมาได้ทางเดียวคือผ่านแม่แบบพื้นที่ (area template) เท่านั้น
- เพิ่มฟิลด์ shape area, shape length และ year of data สำหรับระดับประเทศ พร้อมขยายชนิดฟิลด์ของฟอร์ม (AreaFormModal) ให้รองรับ number/textarea และข้อความ hint ใต้ช่อง
- เพิ่ม validation ของค่าขอบเขตก่อนบันทึก เพื่อให้ค่าที่รูปแบบไม่ถูกต้องแจ้งเตือนที่ฟอร์มแทนที่จะไปพลาดตอนบันทึก
- เพิ่มยูทิลิตี `toCoordinatesPayload` ที่ใช้ร่วมกันทั้งฝั่ง org area และ area template เพื่อจัดการความต่างระหว่าง "ไม่ได้แก้" (ส่งค่าขอบเขตเดิมกลับไป ไม่ให้ถูกล้าง) กับ "ล้างค่า" (ส่ง array ว่าง)
- เพิ่ม endpoint สำหรับอ่านข้อมูลรายตัว (country/province/district by id) ทั้งฝั่ง REST และ mapping GraphQL
- แสดงป้ายที่มา (provenance) บนรายการพื้นที่ ระบุว่าประเทศใดถูกสร้างหรือซิงก์มาจากแม่แบบใด เพื่อแยกพื้นที่ที่สร้างเองกับพื้นที่ที่มาจากแม่แบบ
- อัปเดตคำแปลไทย/อังกฤษ/จีน และปรับไฟล์ตัวอย่าง (areaCURL.sh) ให้ตรงกับ payload ใหม่

**Scope / Context**
- อยู่ในโมดูล System Configuration ส่วน Area Management (CMS) ต่อยอดจากงานแม่แบบพื้นที่ก่อนหน้า โดยเปิดให้พื้นที่ขององค์กรมี geometry ของตัวเองได้โดยไม่ต้องผูกกับแม่แบบ
- หมายเหตุการออกแบบ: การส่ง coordinates เป็น array ว่างเพื่อ "ล้าง" ยังเป็นสมมติฐานที่ยังไม่ยืนยันกับ backend จึงจำกัดไว้ในจุดเดียว (`toCoordinatesPayload`) และฟิลด์ postcode ของอำเภอฝั่ง org ยังเป็น read-only ตาม input ของ backend

**Outcome**
- ผู้ดูแลสามารถกำหนด/แก้ไขขอบเขตและข้อมูลรูปทรงของพื้นที่ระดับองค์กรได้เองบนฟอร์ม การแก้ไขที่ไม่แตะขอบเขตจะไม่ทำให้ขอบเขตเดิมหาย และการเว้นว่างถือว่าไม่มีขอบเขต
- รายการพื้นที่แสดงชัดเจนขึ้นว่าประเทศใดมาจากแม่แบบ ช่วยแยกแยะข้อมูลที่สร้างเองกับที่รับมา ตรวจสอบแล้วว่าโปรเจกต์ผ่าน type check (`tsc -b`) สำเร็จ พร้อมอัปเดตบันทึกการเปลี่ยนแปลงเป็นเวอร์ชัน 0.56.0

### User Area Assignment Tree Fix

**Spending Hour:** 2 hr.

**Activity**
- ปรับหน้าจอมอบหมายพื้นที่ให้ผู้ใช้ (User Area Assignment) ให้อ่านโครงสร้างประเทศ/จังหวัด/อำเภอแบบซ้อนกัน (nested tree) ขององค์กรโดยตรง แทนการดึงรายการแบบ flat สามชุดแล้วนำมา re-join กันในฝั่ง browser
- แก้บั๊กการจัดกลุ่มผิดเมื่อสองประเทศใช้รหัสจังหวัดซ้ำกัน โดยเพิ่ม countryId เข้าไปในการ cascade เลือกระดับจังหวัด และทำ namespace ให้กับ key การขยาย/ยุบและ React key ตามประเทศ
- ยกเลิกการโหลดรายการจังหวัด/อำเภอทั้งหมดล่วงหน้า (length:10000 / length:20000) ที่ใหญ่เกินความจำเป็นของหน้าจอนี้

**Scope / Context**
- อยู่ในโมดูล core ส่วน User Management แท็บ Area ของผู้ใช้ ปัญหาเดิมคือการติ๊กจังหวัดหรือทั้งประเทศอาจไปติ๊กอำเภอของอีกประเทศที่บังเอิญมีรหัสจังหวัดเดียวกัน และจังหวัดรหัสซ้ำจะขยาย/ยุบพร้อมกัน

**Outcome**
- การมอบหมายพื้นที่ให้ผู้ใช้ถูกต้องแม้มีรหัสจังหวัดซ้ำข้ามประเทศ การขยาย/ยุบและการ cascade เลือกทำงานแยกกันตามประเทศ และลดปริมาณข้อมูลที่โหลดตอนเปิดหน้าจอ ตรวจสอบแล้วว่าผ่าน type check (`tsc -b`) สำเร็จ พร้อมอัปเดตบันทึกการเปลี่ยนแปลงเป็นเวอร์ชัน 0.56.1
