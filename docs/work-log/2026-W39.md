### Administrative Boundary Matching Fix and Build Tooling Hardening

**Spending Hour:** 2.5 hr.

**Activity**
- แก้ไข logic การจับคู่รหัสอำเภอ (district) ระหว่างข้อมูลพื้นที่ขององค์กรกับไฟล์ geometry ที่สร้างจากสคริปต์ ซึ่งเดิมใช้รหัสอำเภอแบบสั้น (intra-province) ไปเทียบกับรหัสเต็มแบบ TIS-1099 ทำให้จับคู่ boundary ผิดหรือไม่เจอในบางอำเภอ
- แก้ไขการจับคู่ boundary ระดับประเทศ ซึ่งเดิมพยายามเทียบรหัสประเทศจริงกับข้อมูล geometry ตัวอย่างเดียวที่มีอยู่ ทำให้ boundary ระดับประเทศไม่แสดงผลเลย ปรับให้ทุก node ระดับประเทศใช้ geometry เดียวกันแทนการค้นหาด้วยรหัส
- ย้ายไฟล์ข้อมูลดิบต้นทางของสคริปต์ boundary (`boundary-source-data/`) ออกจากใต้ `src/` เพื่อไม่ให้ Tailwind v4 content scanner สแกนไฟล์ขนาดใหญ่เหล่านี้จนค้าง พร้อมจำกัดขอบเขตการสแกนของ tailwindcss import ให้ชัดเจน (`source(".")`) เป็นการแก้ที่ต้นตอ
- ปรับ dependency ของโปรเจกต์ (เพิ่ม `@types/geojson`, อัปเดต `dayjs`) ให้สอดคล้องกับงานด้าน geometry/type

**Scope / Context**
- เป็นบั๊กที่หลงเหลือจากการย้ายไปใช้ TopoJSON ทั่วประเทศเมื่อวาน (2026-09-22) พบขณะตรวจสอบผลลัพธ์ว่า boundary บางอำเภอกับระดับประเทศไม่ตรง/ไม่ขึ้น

**Outcome**
- Boundary ระดับอำเภอจับคู่กับพื้นที่ขององค์กรได้ถูกต้องครบทุกจังหวัด และ boundary ระดับประเทศแสดงผลได้แล้ว
- ลดความเสี่ยงที่เครื่องมือ build จะค้างจากไฟล์ข้อมูลดิบขนาดใหญ่ในอนาคต
