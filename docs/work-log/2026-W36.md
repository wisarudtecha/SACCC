**Scope / Context**
- อยู่ในโมดูล CMS ส่วนแผนที่ทั้งหมด ได้แก่ การเลือกที่อยู่ตอนสร้างเคส แผนที่ในหน้ารายละเอียดเคส แผนที่ติดตามเจ้าหน้าที่ และหน้าวาดขอบเขตพื้นที่ในส่วนตั้งค่าระบบ
- ที่มาของงานคือ API key ของ ArcGIS ถูกจำกัดโดเมนไว้ และ build ของ qa/sit/production ไม่มี key ติดไปด้วย ทำให้ basemap ตกไปใช้ tile รุ่นเก่าและการค้นหาที่อยู่กับการคำนวณเส้นทางใช้งานไม่ได้ จึงต้องมีทางเลือกผู้ให้บริการรายที่สองที่รองรับข้อมูลไทยได้ดี
- เลือกวิธีสลับผู้ให้บริการตอน build และโหลดเฉพาะ SDK ของผู้ให้บริการที่เลือก เพราะถ้า import ทั้งสองไว้ในไฟล์เดียวกัน bundle ของสภาพแวดล้อมที่เลือก Longdo จะยังต้องดาวน์โหลด SDK ของ ArcGIS ซึ่งเป็นก้อนที่ใหญ่ที่สุดของแอปอยู่ดี
- ผลจาก spike เปลี่ยนแผนงานส่วนเส้นทาง เพราะ API เส้นทางของ Longdo ส่งกลับมาเฉพาะคำแนะนำการเดินทาง ระยะทาง และเวลา แต่ไม่มีข้อมูลรูปเส้นสำหรับวาดบนแผนที่ จึงย้ายส่วนนั้นไปทำทีหลังด้วยวิธีอื่น
- ค่าเริ่มต้นยังเป็น ArcGIS และยังไม่มีสภาพแวดล้อมใดถูกสลับไปใช้ Longdo งานส่วนนี้จึงยังไม่มีผลต่อผู้ใช้

**Outcome**
- แผนที่ทั้งสี่จุดในระบบพูดกับชนิดข้อมูลกลางแทนคลาสของ ArcGIS โดยตรงแล้ว การเพิ่มผู้ให้บริการรายใหม่ไม่ต้องแก้ทุกจุดที่เรียกใช้อีกต่อไป
- มีแผนที่ Longdo พร้อมการค้นหาสถานที่และการแสดงขอบเขตการปกครองใช้งานได้แล้วเมื่อตั้งค่าให้เลือกผู้ให้บริการรายนี้
- สภาพแวดล้อมที่เลือก Longdo จะไม่ดาวน์โหลด SDK ของ ArcGIS เลย (ยังไม่ได้วัดขนาด bundle จริง)
- ไฟล์เดิมที่ถูกแก้มีจำนวนบรรทัดลดลงสุทธิ เพราะตรรกะที่ย้ายออกไปอยู่ใน service และแค็ตตาล็อก basemap แทนที่จะกระจายอยู่ในคอมโพเนนต์แผนที่
- งานยังไม่จบ ส่วน overlay เจ้าหน้าที่ เส้นทาง หน้าวาดขอบเขต และการตั้งค่าสภาพแวดล้อม ยังค้างอยู่ จึงยังไม่ commit เข้า repository ในรอบนี้

- รื้อคอมโพเนนต์แผนที่ฝั่ง ArcGIS ให้ผูกกับชนิดข้อมูลกลางแทนคลาสของ SDK ย้ายนิยาม prop ทั้งหมดไปไว้ในไฟล์ชนิดข้อมูลร่วม ย้ายการเรียก reverse geocode ไปใช้ service แยก และย้ายส่วนสร้าง basemap ของ ArcGIS ออกไปไฟล์เฉพาะผู้ให้บริการ เหลือแค็ตตาล็อก basemap กลางที่ไม่ import SDK ใด ๆ

- ย้ายฟังก์ชัน ringsSignature ซึ่งเป็น helper บริสุทธิ์ออกจากไฟล์ที่ import SDK ของ ArcGIS ไปไว้รวมกับ helper เรขาคณิตอื่นใน utils แล้วให้ sketch layer ทั้งสองฝั่งเรียกจากที่เดียวกัน เพราะการ import จากไฟล์เดิมดึง Esri geometry ~185KB เข้าไปอยู่ใน bundle ของ Longdo โดยไม่จำเป็น บันทึกเป็นกฎ anti-regression ว่าการ import binding เดียวจากโมดูลก็ยังลากทั้ง import graph ของโมดูลนั้นมาด้วย
- ปรับตำแหน่งการ์ดพิกัด/ที่อยู่บนแผนที่ใหญ่ให้ไม่ทับแถบเครดิตผู้ให้บริการที่ SDK วาดชิดขอบล่าง

- เพิ่มคำแปลที่เกี่ยวกับการค้นหาสถานที่บนแผนที่ครบทั้งสามภาษา
- ตรวจ tsc ทั้ง repo ผ่านสะอาดแล้วจึง commit งานแผนที่ทั้งก้อนเข้า repository (งานส่วนนี้ค้างมาตั้งแต่วันจันทร์เพราะยัง build ไม่ผ่าน)

**Scope / Context**

- ค่าเริ่มต้นยังเป็น ArcGIS และยังไม่มีสภาพแวดล้อมใดสลับไปใช้ Longdo งานส่วนนี้จึงยังไม่มีผลต่อผู้ใช้

**Outcome**

### Service Type Price and Screen Improvements

**Activity**

- เพิ่มคอลัมน์สถานะ active/inactive ในรายการ และปุ่ม toggle สถานะในฟอร์ม
- เปิดการอัปโหลดรูปแนบของประเภทบริการกลับมา และกำหนด path การอัปโหลดเป็น service เพิ่ม mapping ฝั่ง GraphQL ให้ path นี้ไปที่ operation ของ CRM เพื่อตัด warning ตอน dev
- เพิ่ม dialog ยืนยันก่อนสร้างหรือแก้ไข โดยฟอร์มจะพัก payload ไว้ก่อน แล้วยิง mutation หลังผู้ใช้กดยืนยัน
- แก้การส่งข้อมูลตอนแก้ไขให้ระบุ record ด้วย identifier ที่ API ต้องการ (ค่า UUID ของ serviceId ไม่ใช่ integer PK) รูปแบบเดียวกับที่แก้ให้ appointment type ก่อนหน้านี้
- ปรับการอ่านสถานะผลลัพธ์จาก envelope ที่ส่ง status มาเป็นสตริง "0"/"-1" และดึงข้อความจาก field message/desc/msg ให้ครบทั้งกรณีสำเร็จและล้มเหลว
- เอา logic เดิมที่ยัด File เปล่าเข้าไปตอนกดแก้ไขออก เพราะทำให้ทุกการแก้ไขถูกส่งผ่านเส้นทาง multipart โดยไม่จำเป็น
- แก้ mapping ฝั่ง GraphQL ของ /service_type ให้เป็นแบบแยกตาม HTTP method (GET = ดึงรายการ, POST = สร้าง, PUT/PATCH = แก้ไข) จากเดิมที่ entry แบบไม่ระบุ method ทำให้คำสั่งสร้างถูกคอมไพล์เป็น query ดึงรายการ
- เพิ่มคำแปลของฟิลด์ราคาครบทั้งสามภาษา

**Scope / Context**
- อยู่ในโมดูล CMS ส่วนจัดการประเภทบริการ (CRM > Services) และชั้น API/GraphQL mapping ที่เกี่ยวข้อง
- ต่อเนื่องจากชุดงานแก้ไขฝั่ง service type / appointment type ที่ทำมาก่อนหน้า บั๊กเรื่อง identifier ตอนแก้ไขเป็นบั๊กประเภทเดียวกับที่เคยเจอใน appointment type
- backend ต้องการฟิลด์ราคาสำหรับประเภทบริการ จึงต้องเปิดฟิลด์นี้ในฟอร์มและส่งค่าไปด้วย

**Outcome**
- ประเภทบริการมีราคากำหนดได้และแสดงในรายการ พร้อมสถานะ active/inactive ที่ปรับได้จากฟอร์มเดียวกัน
- การแก้ไขประเภทบริการบันทึกได้แล้ว จากเดิมที่ถูก API ปฏิเสธเพราะอ้าง record ผิด
- การสร้างและแก้ไขมีขั้นตอนยืนยัน และผู้ใช้เห็นข้อความจากเซิร์ฟเวอร์ทั้งตอนสำเร็จและล้มเหลว
- คำสั่งสร้างประเภทบริการไม่ถูกส่งเป็น query ดึงรายการอีกต่อไป และการแก้ไขไม่วิ่งผ่านเส้นทาง multipart โดยไม่จำเป็น
