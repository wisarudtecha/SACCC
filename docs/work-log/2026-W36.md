### Map Provider Abstraction and Longdo Map Integration

**Spending Hour:** 6 hr.

**Activity**
- ทำ spike ทดสอบ SDK และ REST API ของ Longdo Map ด้วยหน้าทดสอบแยกต่างหากก่อนเริ่มเขียนโค้ดจริง เพื่อตอบคำถามที่เอกสารของผู้ให้บริการไม่ได้ระบุไว้ ได้แก่ รูปแบบพิกัด รูปแบบ basemap ที่ใช้ได้แบบไม่มีค่าใช้จ่าย ลำดับการวาด overlay การอ่านค่ารูปหลายเหลี่ยมที่แก้ไขได้ และรูปแบบข้อมูลที่ API เส้นทางส่งกลับมา
- แยกสัญญาการใช้งานแผนที่ออกจาก SDK ของผู้ให้บริการ โดยสร้างชุดชนิดข้อมูลกลางสำหรับพิกัด ผลการค้นหาที่อยู่ มุมมองแผนที่ และเส้นทาง แล้วแทนที่ชนิดข้อมูลเฉพาะของ ArcGIS ที่รั่วเข้าไปอยู่ใน hook ฟอร์ม และหน้ารายละเอียดเคส
- แยกงานเรียก API ค้นหาที่อยู่และคำนวณเส้นทางออกจากคอมโพเนนต์ที่วาดแผนที่ มาเป็น service แยกต่อผู้ให้บริการ และย้ายตรรกะการคำนวณเส้นทางของ ArcGIS ออกจาก hook เดิม ให้ hook เหลือหน้าที่เฉพาะการ cache และควบคุมความถี่ในการเรียก
- แยกรายการ basemap ออกเป็นแค็ตตาล็อกกลางที่ไม่ผูกกับ SDK พร้อมรายการเฉพาะของแต่ละผู้ให้บริการ และตั้งชื่อคอมโพเนนต์กับไฟล์ให้เป็นกลาง ไม่อ้างอิงชื่อผู้ให้บริการรายใดรายหนึ่ง
- เพิ่มการตั้งค่าเลือกผู้ให้บริการแผนที่และ API key ของ Longdo ใน config ระดับโปรเจกต์ โดยค่าที่ไม่ถูกต้องหรือไม่ได้ตั้งไว้จะย้อนกลับไปใช้ ArcGIS ตามเดิม
- เขียนส่วนแสดงผลแผนที่ด้วย Longdo ทั้งการตั้งค่า SDK ชนิดข้อมูล การแปลงรูปทรง สัญลักษณ์ ช่องค้นหาสถานที่ (Longdo ไม่มี widget ค้นหาให้เหมือน ArcGIS) overlay ขอบเขตการปกครอง และกำลังทำ overlay ตำแหน่งเจ้าหน้าที่อยู่
- เพิ่มคำแปลที่เกี่ยวข้องกับการค้นหาสถานที่บนแผนที่ครบทั้งสามภาษา
- แก้ปัญหา render วนไม่รู้จบตอนเปิดฟอร์มสร้างเคส ซึ่งเกิดจากฟังก์ชันแปลภาษาถูกสร้างใหม่ทุกรอบ render จึงไม่มีวันตรงกับ dependency เดิม ร่วมกับ effect ที่เขียนค่าว่างชุดใหม่ลง state ทุกครั้งโดยไม่ตรวจก่อน แก้แล้วบันทึกเป็นกฎป้องกันไว้ในเอกสาร anti-regression

**Scope / Context**
- อยู่ในโมดูล CMS ส่วนแผนที่ทั้งหมด ได้แก่ การเลือกที่อยู่ตอนสร้างเคส แผนที่ในหน้ารายละเอียดเคส แผนที่ติดตามเจ้าหน้าที่ และหน้าวาดขอบเขตพื้นที่ในส่วนตั้งค่าระบบ
- ที่มาของงานคือ API key ของ ArcGIS ถูกจำกัดโดเมนไว้ และ build ของ qa/sit/production ไม่มี key ติดไปด้วย ทำให้ basemap ตกไปใช้ tile รุ่นเก่าและการค้นหาที่อยู่กับการคำนวณเส้นทางใช้งานไม่ได้ จึงต้องมีทางเลือกผู้ให้บริการรายที่สองที่รองรับข้อมูลไทยได้ดี
- เลือกวิธีสลับผู้ให้บริการตอน build และโหลดเฉพาะ SDK ของผู้ให้บริการที่เลือก เพราะถ้า import ทั้งสองไว้ในไฟล์เดียวกัน bundle ของสภาพแวดล้อมที่เลือก Longdo จะยังต้องดาวน์โหลด SDK ของ ArcGIS ซึ่งเป็นก้อนที่ใหญ่ที่สุดของแอปอยู่ดี
- ผลจาก spike เปลี่ยนแผนงานส่วนเส้นทาง เพราะ API เส้นทางของ Longdo ส่งกลับมาเฉพาะคำแนะนำการเดินทาง ระยะทาง และเวลา แต่ไม่มีข้อมูลรูปเส้นสำหรับวาดบนแผนที่ จึงย้ายส่วนนั้นไปทำทีหลังด้วยวิธีอื่น
- ค่าเริ่มต้นยังเป็น ArcGIS และยังไม่มีสภาพแวดล้อมใดถูกสลับไปใช้ Longdo งานส่วนนี้จึงยังไม่มีผลต่อผู้ใช้

**Outcome**
- แผนที่ทั้งสี่จุดในระบบพูดกับชนิดข้อมูลกลางแทนคลาสของ ArcGIS โดยตรงแล้ว การเพิ่มผู้ให้บริการรายใหม่ไม่ต้องแก้ทุกจุดที่เรียกใช้อีกต่อไป
- มีแผนที่ Longdo พร้อมการค้นหาสถานที่และการแสดงขอบเขตการปกครองใช้งานได้แล้วเมื่อตั้งค่าให้เลือกผู้ให้บริการรายนี้
- สภาพแวดล้อมที่เลือก Longdo จะไม่ดาวน์โหลด SDK ของ ArcGIS เลย (ยังไม่ได้วัดขนาด bundle จริง)
- ไฟล์เดิมที่ถูกแก้มีจำนวนบรรทัดลดลงสุทธิ เพราะตรรกะที่ย้ายออกไปอยู่ใน service และแค็ตตาล็อก basemap แทนที่จะกระจายอยู่ในคอมโพเนนต์แผนที่
- งานยังไม่จบ ส่วน overlay เจ้าหน้าที่ เส้นทาง หน้าวาดขอบเขต และการตั้งค่าสภาพแวดล้อม ยังค้างอยู่ จึงยังไม่ commit เข้า repository ในรอบนี้

- แก้ตัวเลขสรุปในกราฟแนวโน้มของ dashboard ที่แสดงค่าของเดือนล่าสุดเพียงเดือนเดียว ทั้งที่ป้ายกำกับสื่อว่าเป็นค่ารวมของทั้งช่วง ให้คำนวณเป็นผลรวมของทุกจุดข้อมูล
- ปรับแถวป้ายชื่อเดือนใต้กราฟให้จำนวนคอลัมน์ตรงกับจำนวนจุดข้อมูลจริง และแสดงค่ากำกับครบทุกจุด จากเดิมที่แสดงเพียงสามจุด
- จำกัดความกว้างของป้ายหมวดหมู่บนการ์ดคลังความรู้ พร้อมแสดงชื่อเต็มเมื่อชี้เมาส์ และลบตัวแปรที่ไม่ได้ใช้งานแล้วออก เพราะทำให้ build ไม่ผ่านภายใต้การตรวจตัวแปรที่ประกาศแล้วไม่ได้ใช้

**Scope / Context**
- อยู่ในโมดูล KMS ครอบคลุมหน้าบทความ แบนเนอร์ broadcast ไฟล์ แหล่งข้อมูล และ dashboard ของคลังความรู้
- โมดูลนี้ดึงข้อมูลด้วยไลบรารีคนละตัวกับโมดูล CMS และตั้งค่าอายุข้อมูลไว้ 30–60 วินาที ทำให้การกลับเข้าหน้าจอภายในช่วงเวลาดังกล่าวได้ข้อมูลชุดเดิม รวมถึงหลังจากเพิ่งแก้ไขบทความไป
- เนื้อหาบางส่วนของงานนี้มาจากการรวมโค้ดของงานฝั่ง KMS ที่ทำคู่ขนานกัน ไม่ได้เขียนขึ้นใหม่ทั้งหมดในรอบนี้
- วิธีที่ใช้เป็นการทำซ้ำรูปแบบเดียวกันใน hook หลายตัว และดึงข้อมูลใหม่ทุกครั้งที่เปลี่ยนหน้า รวมถึงกรณีที่ข้อมูลไม่มีทางเปลี่ยน บันทึกไว้เป็นประเด็นที่ควรปรับให้แคบลงในภายหลัง

**Outcome**

- ตัวเลขสรุปในกราฟแนวโน้มตรงกับสิ่งที่ป้ายกำกับสื่อ และทุกเดือนบนกราฟมีป้ายชื่อและค่ากำกับครบ
- ชื่อหมวดหมู่ยาว ๆ ไม่ล้นการ์ดอีกต่อไป และ build กลับมาผ่าน
