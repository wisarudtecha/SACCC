### API Coverage Completion for the Newer API Layer

**Spending Hour:** 4.5 hr.

**Activity**

- ไล่ตรวจ endpoint ที่ยังไม่ถูกแมปเข้า API layer ใหม่ทีละรายการ และแก้เฉพาะรายการที่ฝั่งเซิร์ฟเวอร์รองรับจริง ได้แก่ endpoint สร้างที่ใช้ suffix /add, การ publish/version/active ของฟอร์มที่ถูก route แบบมี id กลืนไปก่อน, role permission และการสร้าง customer service
- เพิ่มกลไกเปลี่ยนชื่อฟิลด์ในชั้น mapping เพื่อให้ชื่อฟิลด์ที่ฝั่งเรียกใช้ส่งอยู่ยังใช้ได้ ขณะที่ payload ที่ส่งไปเซิร์ฟเวอร์ใช้ชื่อที่ input type กำหนด
- แก้การลบผู้ใช้ให้วิ่งผ่านชั้น query แทน fallback ของ container ที่ยิง REST ตรงไปยัง URL ที่เซิร์ฟเวอร์ไม่มีให้บริการ และไม่รีเฟรชรายการหลังลบ
- เขียนสคริปต์ตรวจ mapping ทั้งหมดกับ schema จริงของเซิร์ฟเวอร์ และรันซ้ำได้ทุก environment
- เขียน unit test ครอบทุก path ที่เพิ่มและที่แก้ รวมถึงเคสที่ path แบบมี id ต้องไม่กลืน path แบบ literal

**Scope / Context**

- เมื่อเปิดใช้ API layer ใหม่ จะไม่มี fallback กลับไป REST ถ้า mapping ผิดผู้ใช้จะเจอ error ทันที แต่ไม่มีอะไรใน type check หรือ lint จับได้ เพราะ mapping เป็นเพียงข้อความ
- บาง endpoint ยังไม่ถูกแมปโดยตั้งใจ เพราะ input type ของเซิร์ฟเวอร์ยังไม่รองรับกรณีที่ฝั่งเรียกใช้ต้องส่ง (order item แบบมีเฉพาะ part) การแมปให้ดูครบจะทำให้เส้นทางที่ REST รองรับอยู่แล้วพัง

**Outcome**

- การกระทำของผู้ดูแลระบบบน API layer ใหม่ทำงานได้จริง ทั้งการสร้างโครงสร้างองค์กร บทบาท สกิล ฟอร์ม และการลบผู้ใช้
- การลบผู้ใช้ลบแถวออกจากรายการทันทีโดยไม่ต้องโหลดหน้าใหม่
- มีเครื่องมือที่บอกได้ทันทีว่า mapping ใดเซิร์ฟเวอร์ไม่รู้จัก ก่อนผู้ใช้เป็นคนเจอ

### Engineering Guidelines and Anti-Regression Lessons

**Spending Hour:** 1 hr.

**Activity**

- อัปเดตแนวทางของโปรเจกต์ให้ตรงกับสภาพจริงของชุดทดสอบ ตำแหน่งของ flag และข้อจำกัดของแต่ละ environment

**Scope / Context**

- บทเรียนเดิมส่วนหนึ่งถูกจดไว้แล้ว แต่ยังไม่ถูกทำให้เป็นกฎที่ตรวจสอบได้ตอนลงมือ
