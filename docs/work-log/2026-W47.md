### WebSocket Access-Token Authentication

**Spending Hour:** 4 hr.

**Activity**

- เปลี่ยนการยืนยันตัวตนของ websocket จากที่ฝั่งเซิร์ฟเวอร์เชื่อ orgId และ username ที่ client แจ้งมา เป็นการแนบ access token ไปกับ frame แรกที่ใช้สมัครรับข้อมูล
- รวมส่วนประกอบของ token carrier ไว้ในโมดูลเดียว ทั้งการอ่าน token ผ่าน TokenManager การสร้าง frame และการตัดสินใจว่าจะเชื่อมต่อใหม่หรือหยุด
- ให้ session ที่ไม่มี token ไม่ถูกเปิด socket เลย และรายงานสถานะเป็น unauthorized แทนการเปิดแล้วรอให้เซิร์ฟเวอร์ตัด
- จัดการรหัสปิด 4401/4403 ด้วยการต่ออายุ token หนึ่งครั้งแล้วเชื่อมต่อใหม่ ถ้ายังถูกปฏิเสธให้หยุดและรายงานสถานะ ไม่วนซ้ำ
- แก้ตัวนับรอบการเชื่อมต่อใหม่ที่ไม่เคยรีเซ็ตจริง เพราะถูกล้างทุกครั้งที่เกิด error ทำให้เพดานจำนวนรอบไม่มีผล ให้รีเซ็ตเมื่อเชื่อมต่อสำเร็จเท่านั้น
- ให้ frame อื่นทั้งหมด ทั้ง heartbeat และคำสั่งอื่น ไม่แนบ token ตามค่าเริ่มต้น เพื่อลดจุดที่ token จะหลุดออกไป
- ปรับ type ของสถานะการเชื่อมต่อที่ dashboard ใช้ ให้อ้างอิงตัวเดียวกันแทนการประกาศซ้ำ
- เขียน probe ขนาดเล็กสำหรับดักดู frame จริงในเครื่อง และ unit test ทั้งระดับฟังก์ชันและระดับ provider
- อัปเดตเอกสารสัญญา event ของ websocket แผนงานฉบับเต็ม และคำขอถึงฝั่งเซิร์ฟเวอร์ให้ตรงกับสิ่งที่ส่งจริง

**Scope / Context**

- browser ไม่สามารถใส่ header ในคำขอ upgrade ของ WebSocket ได้ จึงต้องเลือกช่องทางอื่น
- ลองฝาก token ผ่าน Sec-WebSocket-Protocol แล้ว แต่ handshake ล้มทั้งเส้นถ้าเซิร์ฟเวอร์ไม่สะท้อน protocol กลับ และตั้งชื่อ header เป็น Authorization ไม่ได้ จึงตัดทิ้งแล้วใช้ฟิลด์ใน frame แทน
- ฝั่งเซิร์ฟเวอร์ยังไม่ได้ตรวจ token จึงยังไม่ถือว่า socket ได้รับการยืนยันตัวตนจริง บันทึกเป็นคำขอถึง backend ไว้แล้ว
- ต้องคงพฤติกรรมเดิมของกรณีที่ token หมดอายุ ไม่ให้ผู้ใช้ต้องรีเฟรชหน้าเอง

**Outcome**

- token ถูกส่งไปกับ frame สมัครรับข้อมูล และไม่ถูกส่งซ้ำในทุก frame
- session ที่หมดอายุได้ต่ออายุอัตโนมัติหนึ่งครั้ง และได้สถานะที่บอกตามจริงเมื่อถูกปฏิเสธ
- จำนวนรอบการเชื่อมต่อใหม่มีเพดานจริง ไม่เกิด loop ของการต่ออายุ token และไม่มี socket ที่เปิดค้างแบบไม่ยืนยันตัวตน
- มีเครื่องมือและ test ที่ยืนยันได้ว่า frame ที่ออกไปมีอะไรบ้าง

### Staff Tracking Refresh Cadence

**Activity**

- ให้โหมด manual ของการรีเฟรชตำแหน่งหยุดตัวจับเวลา แต่ยังคงให้ตัวนับ ETA/TTL เดินต่อไปเพราะเป็นการแสดงผลเท่านั้น
- ใส่พื้นล่างของรอบเวลาโหมด auto และหยุด polling เมื่อแท็บถูกย้ายไปอยู่เบื้องหลัง
- เพิ่มช่องกรอกช่วงเวลาในหน้าตั้งค่าพร้อมบอกค่าที่มีผลจริงหลังถูกบังคับด้วยพื้นล่าง

**Scope / Context**

- การรีเฟรชตำแหน่งเป็นคำขอหนึ่งครั้งต่อเคสที่เปิดอยู่ การตั้งค่าที่ต่ำเกินไปจึงกระทบ server ตรง ๆ และต้องมีพื้นล่างบังคับใช้ ไม่ใช่แค่เตือนในฟอร์ม
- ตัวนับ ETA/TTL ไม่ได้เรียกบริการใด เป็นเพียงการวาดใหม่ จึงต้องเดินต่อในทุกโหมด

**Outcome**

- ผู้ดูแลกำหนดรอบรีเฟรชตำแหน่งได้ และระบบไม่ยิงคำขอถี่กว่านั้นแม้ค่าที่บันทึกจะต่ำกว่า
- แท็บที่ไม่ได้เปิดอยู่ไม่กินคำขอ และตัวนับยังเดินถูกต้องทุกโหมด

### Assignment Mode per Case Sub-Type

**Spending Hour:** 0.75 hr.

**Activity**

- เปลี่ยนการตั้งค่าโหมดมอบหมายงานจากสวิตช์เดียวทั้งองค์กร เป็นตารางตามประเภทและประเภทย่อยของเคส โดยแยกสองขั้น (ผู้รับผิดชอบ และการมอบเคส) และมีสถานะ "ไม่ได้ตั้งค่า"
- ทำตัวควบคุมแบบ segmented ที่เป็น radiogroup จริง ใช้ลูกศรและ Home/End ได้ และให้ screen reader อ่านสถานะถูกต้อง
- เพิ่มตัวแปลงข้อมูลระหว่างเอกสารที่เก็บกับฟอร์ม โดยคงฟิลด์ที่หน้าจอยังไม่รู้จักไว้ไม่ให้หายตอนบันทึก และตัดรายการซ้ำของประเภทย่อยเดียวกัน
- รวมการบันทึกของการตั้งค่าทั้งหน้าไว้ที่หน้าเดียว (แผนที่ + กติกามอบหมาย + โหมด) พร้อมตรวจค่าและพาผู้ใช้ไปยังแท็บที่มีปัญหาเมื่อบันทึกไม่ผ่าน
- เพิ่มคำแปลครบสามภาษา

**Scope / Context**

- backend เก็บทั้งหน้าเป็นเอกสาร JSON ก้อนเดียว การบันทึกจึงแทนที่ทั้งก้อน ตัวแปลงต้อง merge บนเอกสารเดิม ไม่ใช่สร้างใหม่จาก type ฝั่งเรา ไม่งั้นฟิลด์ที่ยังไม่มี UI จะหายไป
- โหมด "ไม่ได้ตั้งค่า" แสดงด้วยการไม่มีรายการ ไม่ใช่ค่า token ที่สาม

**Outcome**

- ผู้ดูแลตั้งโหมดอัตโนมัติหรือ manual แยกตามประเภทย่อยของเคสได้ และการบันทึกครั้งเดียวครอบทั้งหน้า
- ค่าที่หน้าจอยังไม่รองรับไม่หายไปเมื่อบันทึก และข้อผิดพลาดพาไปยังแท็บที่ต้องแก้
- ตัวควบคุมใช้ด้วยคีย์บอร์ดและ screen reader ได้

### Bound Form Controls

**Spending Hour:** 0.25 hr.

**Activity**

- แก้ checkbox ที่ไม่ได้ผูกค่าจาก prop จริง ทำให้ค่าที่บันทึกไว้ต้องกดสองครั้งถึงจะเปลี่ยน และติ๊กที่แสดงไม่ตรงกับค่าจริง
- แก้ radio ของตัวกรองในหน้ารายการที่บรรทัดผูกค่า checked ถูกคอมเมนต์ไว้ ทำให้ตัวกรองที่มาจาก URL หรือจากการล้างตัวกรองไม่แสดงสถานะ
- ตรวจตัวควบคุมแบบมี/ไม่มีค่าทั้งโปรเจกต์ (switch, radio, checkbox) และเขียน test ที่พิสูจน์ว่าเวอร์ชันเดิมพังจริง

**Scope / Context**

- input ที่ไม่ได้ผูก checked จะเป็น uncontrolled คือ DOM เริ่มที่ false เสมอ ขณะที่ติ๊กถูกวาดจาก prop ค่ากับภาพจึงไม่ตรงกัน
- อาการที่ผู้ใช้เห็นคือ "ค่าที่บันทึกไว้ไม่ติด" ซึ่งชี้ผิดไปที่การบันทึก จึงต้องตรวจ component ก่อนเชื่อค่าใน DOM

**Outcome**

- ติ๊กถูกและตัวกรองแสดงค่าที่บันทึกไว้ทันที และคลิกครั้งเดียวเปลี่ยนค่าได้
- มี test กันการถอดการผูกค่านี้ออกในอนาคต

**Daily Estimated Effort:** 3 hr.
