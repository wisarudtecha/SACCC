### Knowledge Base Semantic Search Toggle

**Spending Hour:** 1.5 hr.

**Activity**
- เพิ่มตัวเลือกโหมดการค้นหา (Keyword / Semantic) ในแถบ filter ของหน้ารายการบทความ Knowledge Base
- แยกตัวเลือก Semantic Search ออกเป็นคอมโพเนนต์ของตัวเอง พร้อมเชื่อมกับระบบ entitlement: tenant ที่ไม่มีสิทธิ์จะเห็นไอคอนล็อกและเปิด upgrade prompt เมื่อคลิก ส่วน tenant ที่มีสิทธิ์ (Enterprise) จะเห็นป้าย "Coming soon" ในลักษณะ disabled

**Scope / Context**

- เมื่อ backend พร้อม ส่วนที่เตรียมไว้จะสลับจาก query แบบ keyword ปัจจุบันไปใช้ semantic query ได้โดยไม่ต้องแก้ UI ใหม่

**Outcome**
- ผู้ใช้เห็นว่ามีโหมดค้นหาแบบ semantic อยู่ในแพ็กเกจ Enterprise พร้อมเส้นทางอัปเกรดที่ชัดเจน โดยยังค้นหาแบบ keyword ได้ตามปกติทุกองค์กร

### Live Chat Placeholder Pages with Entitlement Gating

**Spending Hour:** 2 hr.

**Activity**
- เพิ่ม route `/lobby-incoming` และ `/chat-history` ในโมดูล cc ครอบด้วย route-level entitlement gate (`entitlement.chat`) ให้สอดคล้องกับ lock badge บน sidebar ที่มีอยู่แล้ว
- สร้าง placeholder page กลางสำหรับหน้า Chat Lobby และ Chat History แจ้งว่าฟีเจอร์ Live Chat อยู่ในแพ็กเกจของ tenant และกำลังพัฒนา (agent assignment, SLA, chat dashboard จะตามมาใน release ถัดไป)
- เพิ่มข้อความแปลของหน้า chat ใน i18n ทั้ง 3 ภาษา
- บันทึกบทเรียนเรื่องการ gate ฟีเจอร์ลง anti-regression skill: ทุก entitlement gate ต้องมีคำตอบทั้งสองฝั่ง ทั้งฝั่งที่ถูกล็อก (upsell UI) และฝั่งที่มีสิทธิ์ (หน้าจริง แม้เป็นเพียง placeholder) ไม่ใช่ใส่ lock badge ที่เมนูแล้วปล่อยให้ route เป็น 404

**Scope / Context**
- งาน entitlement gating เมื่อวันศุกร์ (2026-09-25) ใส่ lock badge ให้เมนู Live Chat ไว้ แต่ยังไม่มี route ปลายทาง ทำให้ tenant ที่ซื้อแพ็กเกจ Professional/Enterprise ซึ่งมีสิทธิ์ใช้ chat คลิกเข้าไปแล้วเจอหน้า 404 แทนที่จะได้สิ่งที่จ่ายเงินไว้
- ฟังก์ชัน chat จริงยังอยู่ในแผนพัฒนา phase ถัดไป placeholder นี้จึงเป็นคำตอบชั่วคราวสำหรับฝั่ง entitled ของ gate

**Outcome**
- Tenant ที่มีสิทธิ์ใช้ Live Chat เปิดเมนู Chat Lobby / Chat History แล้วเห็นหน้าที่อธิบายสถานะฟีเจอร์อย่างถูกต้อง ไม่เจอ 404 อีกต่อไป
- ทั้งสองฝั่งของ entitlement gate ทำงานสมบูรณ์: ฝั่ง locked ได้ upsell prompt, ฝั่ง entitled ได้หน้าจริง

- โหลด map SDK ขนาดใหญ่แบบ lazy พร้อม loading fallback เพื่อไม่ให้ bundle หลักโตขึ้น

**Scope / Context**
- ก่อนหน้านี้การดูตำแหน่งเคสต้องเปิดหน้าแก้ไขเคสเท่านั้น แท็บ Overview มีแต่ข้อความที่อยู่ ทำให้ผู้ใช้ตรวจสอบตำแหน่งเชิงภูมิศาสตร์ไม่ได้จากหน้าสรุป
- เลือกทำเป็น read-only โดยเจตนา เพราะแท็บนี้เป็นหน้าอ่านข้อมูล ไม่ใช่หน้าแก้ไข

**Outcome**
- ผู้ใช้เห็นตำแหน่งที่เกิดเหตุบนแผนที่ได้ทันทีจากแท็บ Overview โดยไม่ต้องเข้าหน้าแก้ไขเคส และเคสเก่าที่ไม่มีพิกัดไม่ถูกแสดงแผนที่ที่อาจสื่อตำแหน่งผิด
