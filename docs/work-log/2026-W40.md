### Linked-Case Management Rework

**Spending Hour:** 6 hr.

**Activity**
- เขียนแท็บ Sub Case ในหน้า Case Detail ใหม่ทั้งหมดเป็น "Linked Cases": แสดงเคสแม่ (parent) ที่เคสปัจจุบันถูกเชื่อมโยงมา และรายการเคสลูกที่เชื่อมโยงเข้ากับเคสนี้ โดยดึงข้อมูลแต่ละเคสจาก API ด้วย id ตรง ๆ แทนการอ่านจาก cache ในเครื่อง
- เพิ่มช่องค้นหาเคส (ตาม id หรือรายละเอียด) และ dialog สำหรับเลือกเคสที่มีอยู่แล้วมาเชื่อมโยงเป็นเคสลูก
- เพิ่มปุ่มยกเลิกการเชื่อมโยงพร้อม dialog ยืนยัน โดยไม่ลบเคสทั้งสองฝั่ง
- แก้เงื่อนไขที่ซ่อนแท็บ Sub Case เมื่อเคสมีข้อมูล sub-case อยู่จริง ทำให้แท็บกลับมาแสดงตามปกติ
- เพิ่ม endpoint ดึงเคสตาม id (mutation) และ lazy query สำหรับ SOP case มาใช้รองรับ flow เชื่อม/ยกเลิกเชื่อมโยง
- เพิ่มข้อความแปลของฟีเจอร์ Linked Cases ใน i18n ทั้ง 3 ภาษา (en/th/cn)

**Scope / Context**
- แท็บ Sub Case เดิมอ่านรายชื่อเคสลูกจาก idb cache (`caseList`) ในเครื่อง ซึ่งเป็นแค่ผลพลอยได้จากการ sync ผ่าน websocket ทำให้เคสลูกที่ยังไม่เคยถูก sync เข้าเครื่องนั้นหายไปแบบไม่มีข้อผิดพลาดแจ้งเตือน และแตกต่างกันไปตามอุปกรณ์/session
- เดิมแท็บนี้ยังมีเงื่อนไขซ่อนตัวเองผิดด้าน (ซ่อนเมื่อมีข้อมูล แทนที่จะซ่อนเมื่อไม่มี) ทำให้ผู้ใช้ที่มีเคสลูกจริงมองไม่เห็นฟีเจอร์นี้เลย
- ฟีเจอร์เชื่อมโยงเคสมีอยู่แล้วฝั่ง backend (`referCaseId`, `referCaseLists`) แต่ฝั่ง UI ยังไม่มีทางสร้าง/ยกเลิกความเชื่อมโยงเอง มีแต่การแสดงผลอย่างเดียว

**Outcome**
- ผู้ใช้เห็นรายการเคสที่เชื่อมโยงครบถ้วนตรงกับข้อมูลจริงบนเซิร์ฟเวอร์ทุกอุปกรณ์ ไม่ขึ้นกับ cache ในเครื่อง
- ผู้ใช้ที่มีสิทธิ์แก้ไขเคสสามารถค้นหาและเชื่อมโยงเคสที่มีอยู่แล้ว หรือยกเลิกการเชื่อมโยงได้เองจากแท็บนี้โดยตรง
- แท็บ Linked Cases แสดงผลให้ผู้ใช้ทุกคนที่มีข้อมูลเชื่อมโยงเห็นตามปกติ ไม่ถูกซ่อนอีกต่อไป
- ตรวจสอบด้วย `tsc -b` (ผ่าน) และ `vitest` (258 tests ผ่านทั้งหมด) ก่อน commit
