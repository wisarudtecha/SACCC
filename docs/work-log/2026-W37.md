### Map Place-Search Results Stacking Fix

**Spending Hour:** 1.5 hr.

**Activity**
- ปรับลำดับการซ้อน (z-index) ของกล่องค้นหาสถานที่บนแผนที่ให้รายการผลลัพธ์ที่ดรอปลงมาอยู่เหนือการ์ดข้อมูลเจ้าหน้าที่ (staff detail / group card) ที่วางอยู่คอลัมน์ซ้ายบนเดียวกัน
- Longdo และ MapTiler: ยกคอนเทนเนอร์ของกล่องค้นหาจาก `z-10` เป็น `z-20` ให้สูงกว่า overlay อื่น ๆ ของแผนที่หนึ่งขั้น พร้อมคอมเมนต์อธิบายเหตุผลไว้ในโค้ด
- ArcGIS: เพิ่มกฎ CSS ใน `globals.css` ให้มุม UI ซ้ายบนของ Search widget (`.esri-view .esri-ui-top-left`) มี `z-index: 20` เนื่องจาก SDK ไม่ได้กำหนด z-index ให้มุมนี้เอง และการ์ดเจ้าหน้าที่ซึ่ง render ทีหลังจึงบังรายการผลการค้นหา ใช้ prefix `.esri-view` ให้ specificity สูงกว่า stylesheet ที่ SDK ฉีดเข้ามาตอน runtime เหมือนกฎ focus outline ที่มีอยู่แล้ว
- ตรวจว่าเฉพาะ Search widget เท่านั้นที่อยู่มุมซ้ายบน (Zoom / Compass ถูกย้ายไป bottom-right แล้ว) การยก z-index ทั้งมุมจึงไม่กระทบคอนโทรลอื่น

**Scope / Context**
- อยู่ในโมดูล CMS ส่วนคอมโพเนนต์แผนที่เลือกที่อยู่ที่ใช้ร่วมกันในหน้าสร้างเคสและแผนที่ติดตามเจ้าหน้าที่ ครอบคลุมทั้งสาม map provider (ArcGIS, Longdo, MapTiler)
- เป็นงานต่อเนื่องหลังงานเพิ่ม map provider และ incident-to-service-center auto-match ที่เพิ่งลงไปเมื่อสัปดาห์ก่อน ซึ่งทำให้การ์ดข้อมูลเจ้าหน้าที่กับกล่องค้นหาสถานที่มาแสดงในพื้นที่คอลัมน์เดียวกันบนแผนที่
- ปัญหาคือเมื่อพิมพ์ค้นหาสถานที่บนแผนที่ที่มีการ์ดเจ้าหน้าที่แสดงอยู่ รายการผลลัพธ์ส่วนล่างจะถูกการ์ดบัง อ่านและกดเลือกไม่ได้
- ไม่มีการเปลี่ยนพฤติกรรมอื่นของแผนที่หรือ layout ของการ์ด แก้เฉพาะลำดับการซ้อน

**Outcome**
- รายการผลการค้นหาสถานที่เปิดทับเหนือการ์ดข้อมูลเจ้าหน้าที่แล้วทั้งสาม map provider ผู้ใช้เห็นและกดเลือกผลลัพธ์ได้ครบทุกรายการ
- การ์ดข้อมูลเจ้าหน้าที่และคอนโทรลอื่นบนแผนที่ยังทำงานและแสดงผลตามเดิม
- repo type-check (`tsc -b`) ผ่านทั้งก้อน

### Organization System Settings — Map & Assignment Defaults

**Spending Hour:** 6.5 hr.

**Activity**
- สร้างหน้า Organization Settings ใหม่ใน Admin / System Configuration เป็น shell แบบ section registry ที่เพิ่มหมวดตั้งค่าใหม่ได้ด้วยการต่อ entry เดียว โดยเวอร์ชันแรกมีสองหมวดคือ Map Settings และ Assignment Rules
- หมวด Map Settings: ฟอร์มกลุ่มการตั้งค่า 5 กลุ่ม (General / Layers / Incident / Staff / Assignment) เลือก map provider และ basemap เริ่มต้น, เปิด-ปิดเครื่องมือบนแผนที่ (place search, boundary layers, address coordinates, การปักหมุดจุดเกิดเหตุ), กำหนดรัศมีรอบจุดเกิดเหตุและการล็อก service center อัตโนมัติ, และควบคุมสิ่งที่แผนที่เจ้าหน้าที่แสดง (marker, movement trail, workload/assigned cases, โหมด auto/manual ของ routing / ETA TTL / tracking พร้อม interval)
- หมวด Assignment Rules: ตัวเลือก routing method และ workload allocation method ระดับองค์กร แยกเป็นสอง option group
- แต่ละหมวดมีปุ่ม Save แบบ atomic ต่อหมวด, ปุ่ม Cancel ที่คืนค่ากลับไปยังค่าที่โหลดล่าสุดโดยไม่เรียก API, การ validate ฝั่ง client พร้อมข้อความ error ราย field, และ banner ค้างเมื่อบันทึกไม่สำเร็จ
- เพิ่ม RTK Query endpoints (`GET`/`PATCH /organizations/{orgId}/map-settings` และ `/assignment-rules`) พร้อม type contract เต็มใน `organization.ts` และลงทะเบียน GraphQL operation mapping ล่วงหน้าเพื่อให้ cut-over ไม่ต้องแก้ FE เพิ่ม
- แยก layer isolation ของ failure ไว้ใน custom hook (`useOrgMapSettings` / `useOrgAssignmentRules`): เมื่อ backend ยังไม่มี route จริง 404 / GraphQL error / shape ไม่ตรง จะ fallback เป็น schema default แทนที่จะขึ้น error state; save ที่ล้มเหลว resolve เป็น `{ ok: false }` ไม่ throw
- เพิ่ม session-scoped stub สำหรับโหมด `VITE_MOCK_API` ให้ demo end-to-end ได้ก่อน backend พร้อม
- ปรับ `Switch` component ให้รองรับ controlled mode (`checked` prop) โดยคงพฤติกรรม uncontrolled เดิมไว้ จำเป็นสำหรับ toggle ที่ต้องสะท้อนข้อมูลที่โหลดแบบ async และรีเซ็ตเมื่อกด Cancel
- เพิ่ม permission ใหม่ `organization_settings.manage`, route `/cms/settings/organization`, และเมนูใน AppSidebar / SuperTopbar ภายใต้ System Configuration
- เพิ่ม i18n key ครบทั้งสามภาษา (en/th/cn) สำหรับทุก label, help text และข้อความ validation ของหน้านี้

**Scope / Context**
- โมดูล CMS ส่วน Admin / System Configuration รวบรวมค่าตั้งต้นระดับองค์กรที่เดิมแก้ได้เฉพาะในไฟล์ config มาไว้ในหน้าจอเดียวที่จำกัดเฉพาะผู้ดูแลระบบ
- ทำงานแบบ FE-first: สัญญา REST/GraphQL และ type ถูกกำหนดจากฝั่ง FE ก่อน backend จะสร้าง route จริง จึงออกแบบให้ทุกจุดที่ต่อ backend ล้มเหลวได้อย่างปลอดภัยและ cut-over เป็น no-op
- หมวด Assignment Rules เป็น configuration อย่างเดียวในเฟสนี้ ยังไม่มี engine ใดนำค่าไปใช้กำหนดการมอบหมายเคสจริง

**Outcome**
- ผู้ดูแลระบบเข้าหน้า Organization Settings ได้จากเมนู System Configuration และปรับค่าเริ่มต้นของแผนที่เคสและวิธีมอบหมายงานได้จากที่เดียว โดยแต่ละหมวดบันทึกแยกกัน
- หน้าจอทำงานได้เต็มรูปแบบในโหมด mock (บันทึกแล้วค่าอยู่จนจบ session) และพร้อมสลับไปใช้ endpoint จริงทันทีที่ backend ปล่อย โดยไม่ต้องแก้โค้ด FE
- `Switch` รองรับทั้ง controlled และ uncontrolled แล้ว โดยไม่กระทบจุดเรียกใช้เดิม
- repo type-check (`tsc -b`) ผ่านทั้งก้อน
