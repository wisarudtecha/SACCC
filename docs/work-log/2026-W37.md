# Work Log — Week 37, 2026

## Monday — 2026-09-07

### Map Place-Search Results Stacking Fix

**Spending Hour:** 1.5 hr.

**Activity**
- ปรับลำดับการซ้อน (z-index) ของกล่องค้นหาสถานที่บนแผนที่ให้รายการผลลัพธ์ที่ดรอปลงมาอยู่เหนือการ์ดข้อมูลเจ้าหน้าที่ (staff detail / group card) ที่วางอยู่คอลัมน์ซ้ายบนเดียวกัน
- Longdo และ MapTiler: ยกคอนเทนเนอร์ของกล่องค้นหาจาก `z-10` เป็น `z-20` ให้สูงกว่า overlay อื่น ๆ ของแผนที่หนึ่งขั้น พร้อมคอมเมนต์อธิบายเหตุผลไว้ในโค้ด
- ArcGIS: เพิ่มกฎ CSS ใน `globals.css` ให้มุม UI ซ้ายบนของ Search widget (`.esri-view .esri-ui-top-left`) มี `z-index: 20` เนื่องจาก SDK ไม่ได้กำหนด z-index ให้มุมนี้เอง และการ์ดเจ้าหน้าที่ซึ่ง render ทีหลังจึงบังรายการผลการค้นหา ใช้ prefix `.esri-view` ให้ specificity สูงกว่า stylesheet ที่ SDK ฉีดเข้ามาตอน runtime เหมือนกฎ focus outline ที่มีอยู่แล้ว
- ตรวจว่าเฉพาะ Search widget เท่านั้นที่อยู่มุมซ้ายบน (Zoom / Compass ถูกย้ายไป bottom-right แล้ว) การยก z-index ทั้งมุมจึงไม่กระทบคอนโทรลอื่น

**Scope / Context**
- อยู่ในโมดูล CMS ส่วนคอมโพเนนต์แผนที่เลือกที่อยู่ที่ใช้ร่วมกันในหน้าสร้างเคสและแผนที่ติดตามเจ้าหน้าที่ ครอบคลุมทั้งสาม map provider (ArcGIS, Longdo, MapTiler)
- เป็นงานต่อเนื่องหลังงานเพิ่ม map provider และ incident-to-service-center auto-match ที่เพิ่งลงไปเมื่อสัปดาห์ก่อน ซึ่งทำให้การ์ดข้อมูลเจ้าหน้าที่กับกล่องค้นหาสถานที่มาแสดงในพื้นที่คอลัมน์เดียวกันบนแผนที่
- ปัญหาคือเมื่อพิมพ์ค้นหาสถานที่บนแผนที่ที่มีการ์ดเจ้าหน้าที่แสดงอยู่ รายการผลลัพธ์ส่วนล่างจะถูกการ์ดบัง อ่านและกดเลือกไม่ได้
- ไม่มีการเปลี่ยนพฤติกรรมอื่นของแผนที่หรือ layout ของการ์ด แก้เฉพาะลำดับการซ้อน

**Outcome**
- รายการผลการค้นหาสถานที่เปิดทับเหนือการ์ดข้อมูลเจ้าหน้าที่แล้วทั้งสาม map provider ผู้ใช้เห็นและกดเลือกผลลัพธ์ได้ครบทุกรายการ
- การ์ดข้อมูลเจ้าหน้าที่และคอนโทรลอื่นบนแผนที่ยังทำงานและแสดงผลตามเดิม
